Midterm Project Requirements

Build one Windows Forms application that manages a single SQL Server table: list, search, filter, add, edit and delete. You choose the subject from the list of 18, or propose your own. Everything you need was taught in weeks 1 to 7 and practised in Labs 1 and 2.

What this is

Your midterm is one small desktop application that you build on your own, in the computer lab, during weeks 8 and 9. It is worth 25 points out of 100 for the whole course.

It is

  • Individual. One student, one project.
  • Built in Visual Studio 2026 with Windows Forms, C# and SQL Server LocalDB, the same tools as the labs.
  • One database table, managed through two windows.
  • Marked against the eleven requirements in this document.

It is not

  • Group work. Two identical projects both score zero.
  • A copy of the Student Registry from Lab 2. That one is the worked example.
  • A design competition. Default Windows controls are fine; working code is the point.
  • A test of anything taught after week 7.
Read this document once, all the way through, before you choose a topic.

Every requirement below is checked when your project is marked. There are no hidden criteria, and there is nothing in the marking table that is not described here.

The midterm covers weeks 1 to 7 only. Nothing below is required, and you lose nothing by leaving it out.

One exception, worth up to 3 bonus points

Add an Export button that saves the rows currently shown in the grid to a .csv file: a SaveFileDialog, one line per row, and Encoding.UTF8 so Georgian letters survive. It earns up to +3. Second tables are not rewarded

A project with two tables and a JOIN does not score higher than a correct one-table project, and it is much easier to get wrong. Build one table well.

Requirements

The eleven requirements

Each one is checked separately. The "Done when" line at the end of each is exactly what is tested on your machine.

1

Project and database

3 pts

A Windows Forms project of your own, with a SQL Server LocalDB database built by a script that is part of the project.

  1. A new project, created with File → New → Project → Windows Forms App (C#, not .NET Framework). Not a copy of a lab folder.
  2. Its own database, named after your subject, for example LibraryDb.
  3. One table, created by a file called database.sql inside the project. A table created only by clicking in SQL Server Object Explorer scores zero for this requirement, because the marker cannot rebuild it.
  4. An Id INT IDENTITY(1,1) PRIMARY KEY column, plus at least five columns besides Id.
  5. At least two different column types. All-text tables are not accepted: use at least one INT, DECIMAL, DATE, TIME or BIT.
  6. The script can be run twice without an error: it checks with IF DB_ID(...) IS NULL and IF OBJECT_ID(...) IS NULL before creating anything.

Example — the shape your script must have

database.sql (start)
IF DB_ID(N'LibraryDb') IS NULL
    CREATE DATABASE LibraryDb;
GO
USE LibraryDb;
GO
IF OBJECT_ID(N'dbo.Books', N'U') IS NULL
CREATE TABLE Books
(
    Id            INT IDENTITY(1,1) PRIMARY KEY,
    Title         NVARCHAR(150) NOT NULL,   -- text
    Author        NVARCHAR(100) NOT NULL,   -- text
    Genre         NVARCHAR(50)  NOT NULL,   -- the column you filter by
    PublishedYear INT           NOT NULL,   -- a number
    Price         DECIMAL(6,2)  NOT NULL,   -- a decimal
    IsAvailable   BIT           NOT NULL    -- true / false
);
GO

Done whenRunning database.sql twice in a row gives no error, and SQL Server Object Explorer shows your database, your table and its columns.

2

The class

1 pt

One C# class that describes one row of your table.

  1. The class name is singular and the table name is its plural: Book → Books.
  2. One property per column, with the same name and a matching type (table below).
  3. At least one calculated property with only a get, worked out from the others and shown in the grid or used for a colour. It is not a column in the database.
SQL typeC# typeControl in the dialog
NVARCHARstringTextBox, or ComboBox for a category
INTintNumericUpDown, read as (int)num.Value
DECIMALdecimalNumericUpDown with DecimalPlaces
DATEDateTimeDateTimePicker, Format = Short
TIMETimeSpanDateTimePicker, Format = Time, read .Value.TimeOfDay
BITboolCheckBox, read .Checked
Book.cs
namespace LibraryCatalogue
{
    public class Book
    {
        public int Id { get; set; }
        public string Title { get; set; }
        public string Author { get; set; }
        public string Genre { get; set; }
        public int PublishedYear { get; set; }
        public decimal Price { get; set; }
        public bool IsAvailable { get; set; }

        // calculated: not a column, worked out from the values above
        public string Availability
        {
            get { return IsAvailable ? "Available" : "On loan"; }
        }
    }
}

Done whenThe project builds, and the grid shows a column for your calculated property.

3

Test data

2 pts

Your project must fill itself with data. The marker will not type rows in by hand.

  1. INSERT statements at the end of the same database.sql, guarded by IF NOT EXISTS (SELECT 1 FROM Books) so a second run does not double them.
  2. At least 15 rows of realistic data. Not test1, test2, aaa.
  3. The values in the column you filter by must be spread out — at least three different categories, so filtering visibly changes the list.
  4. At least three rows must share a word, so searching visibly changes the list.
  5. Georgian text is welcome. Write N'...' before every text value, or it turns into question marks.

The marker does exactly this, on a computer that has never seen your database

  1. Opens View → SQL Server Object Explorer, right-clicks (localdb)\MSSQLLocalDB → New Query, pastes your database.sql and runs it.
  2. Opens your .sln file.
  3. Build → Rebuild Solution, then F5.
This is the most common way to lose points

If those three steps do not produce a working program with data in it, requirements 1, 3 and everything that depends on them fail together. Test it before you submit: in SQL Server Object Explorer right-click your database → Delete, tick Close existing connections, then run your script again and press F5. That is exactly what the marker does.

Done whenThe three steps above, on a LocalDB without your database, give you a grid with 15 or more rows.

4

The repository

2 pts

One class that holds all the SQL, exactly like StudentRepository in Lab 2.

  1. A class called BookRepository (your own name), with public methods for search, add, update and delete.
  2. The connection string is written once, in this class. Its server is (localdb)\MSSQLLocalDB and its Initial Catalog is your database.
  3. Every SqlConnection, SqlCommand and SqlDataReader is inside a using.
  4. The methods take and return your class: List<Book>, Book, an int id. Never a DataTable and never a control.
  5. No form contains SqlConnection, SqlCommand or a line of SQL.
BookRepository.cs — search and count (add, update and delete follow the same pattern)
using Microsoft.Data.SqlClient;

namespace LibraryCatalogue
{
    public class BookRepository
    {
        private readonly string connectionString =
            @"Data Source=(localdb)\MSSQLLocalDB;Initial Catalog=LibraryDb;" +
            "Integrated Security=True;TrustServerCertificate=True";

        public List<Book> Search(string text, string genre)
        {
            List<Book> books = new List<Book>();
            string sql =
                "SELECT Id, Title, Author, Genre, PublishedYear, Price, IsAvailable " +
                "FROM Books " +
                "WHERE (@text = N'' OR Title LIKE @pattern OR Author LIKE @pattern) " +
                "  AND (@genre = N'' OR Genre = @genre) " +
                "ORDER BY Title";

            using (SqlConnection connection = new SqlConnection(connectionString))
            using (SqlCommand command = new SqlCommand(sql, connection))
            {
                command.Parameters.AddWithValue("@text", text);
                command.Parameters.AddWithValue("@pattern", "%" + text + "%");
                command.Parameters.AddWithValue("@genre", genre);
                connection.Open();
                using (SqlDataReader reader = command.ExecuteReader())
                {
                    while (reader.Read())
                    {
                        Book book = new Book();
                        book.Id = (int)reader["Id"];
                        book.Title = (string)reader["Title"];
                        book.Author = (string)reader["Author"];
                        book.Genre = (string)reader["Genre"];
                        book.PublishedYear = (int)reader["PublishedYear"];
                        book.Price = (decimal)reader["Price"];
                        book.IsAvailable = (bool)reader["IsAvailable"];
                        books.Add(book);
                    }
                }
            }
            return books;
        }

        public int CountAll()
        {
            using (SqlConnection connection = new SqlConnection(connectionString))
            using (SqlCommand command = new SqlCommand("SELECT COUNT(*) FROM Books", connection))
            {
                connection.Open();
                return (int)command.ExecuteScalar();
            }
        }
    }
}

Done whenEdit → Find and Replace → Find in Files (Ctrl+Shift+F) for SqlConnection finds it only in the repository.

5

No user text inside SQL

2 pts

Everything the user types reaches SQL Server as a parameter, never as part of the SQL text.

  1. Every value from a TextBox, ComboBox, NumericUpDown, DateTimePicker or CheckBox is passed with command.Parameters.AddWithValue("@name", value).
  2. No SQL string is joined with + to a value the user can change, and no $"...{text}..." inside SQL.
  3. If you offer sorting (requirement 9, option B), the column name comes from a fixed list in your code, chosen by SelectedIndex. A column name cannot be a parameter, so it must never come from the user.

Right and wrong

Right and wrong
// WRONG — the user's text becomes part of the SQL
string sql = "SELECT * FROM Books WHERE Title LIKE '%" + txtSearch.Text + "%'";

// RIGHT — the text is a value, not SQL
string sql = "SELECT * FROM Books WHERE Title LIKE @pattern";
command.Parameters.AddWithValue("@pattern", "%" + txtSearch.Text + "%");

Done whenSearching for ' OR 1=1 -- shows no rows and no error.

6

Two windows

3 pts

A main window with the list, and one dialog used both for adding and for editing.

  1. Form1 is renamed to MainForm, with Visual Studio renaming the references (Lab 2, step 5).
  2. A second form, for example BookForm, with two constructors: an empty one for Add and one that receives a Book for Edit, calling : this().
  3. Each column has the control that fits its type (table in requirement 2). A category column uses a ComboBox with DropDownStyle = DropDownList, so nobody can type a fourth category by mistake.
  4. Every control you use in code has a real name with a prefix: txtTitle, cmbGenre, numPrice, dtpPurchased, chkAvailable, btnSave, dgvBooks, lblStatus.
  5. In the dialog, AcceptButton is the Save button and CancelButton is the Cancel button. Save sets DialogResult = DialogResult.OK.
  6. In the main window, the grid has Anchor = Top, Bottom, Left, Right, so it grows with the window. The Id column is hidden and the headers are readable words, not PublishedYear.
  7. One visual rule that depends on the data: a row colour set in CellFormatting, or a calculated property that shows a word instead of True/False.

The visual rule — one example that counts

MainForm.cs
private void dgvBooks_CellFormatting(object sender, DataGridViewCellFormattingEventArgs e)
{
    Book book = dgvBooks.Rows[e.RowIndex].DataBoundItem as Book;
    if (book != null && !book.IsAvailable)
        e.CellStyle.BackColor = Color.FromArgb(252, 228, 226);
}
CellFormatting is not a double-click event

Connect it from the ⚡ Events list in the Properties window (Lab 2, step 14). If the method exists but nothing changes colour, it is not connected.

Done whenDragging the window corner grows the grid; in the dialog, Enter saves and Esc cancels; and at least one row looks different because of its data.

7

Working CRUD

6 pts

The four operations, all saving to SQL Server. This is the largest single block of marks.

  1. Create — Add opens the empty dialog; Save adds the row, and the grid shows it immediately, without restarting.
  2. Read — the grid shows every column that matters, when the program opens.
  3. Edit — Edit, or a double-click on a row, opens the dialog already filled in with that row's values. Saving changes only that row.
  4. Delete — asks first with MessageBoxButtons.YesNo. No deletes nothing.
  5. Cancel or the ✕ in the dialog changes nothing. Check form.ShowDialog() == DialogResult.OK before saving.
  6. Edit or Delete with no row selected shows a message instead of crashing.
  7. A status message after each of the three actions: added, updated, deleted. A Label under the grid is enough.
MainForm.cs — the pattern for Edit
private void btnEdit_Click(object sender, EventArgs e)
{
    if (dgvBooks.CurrentRow == null) return;
    Book selected = (Book)dgvBooks.CurrentRow.DataBoundItem;

    using (BookForm form = new BookForm(selected))
    {
        if (form.ShowDialog() == DialogResult.OK)
        {
            repository.Update(form.CurrentBook);
            lblStatus.Text = "Book updated.";
        }
    }
    LoadBooks();
}
Changes that vanish

If a row appears in the grid but is gone after a restart, you added it to the list and never called the repository. The grid shows what is in memory; only the repository writes to the database.

Done whenYou add a row, edit it, delete it, then close the program and press F5 again — and the grid agrees with what you did.

8

Search

3 pts

A search box above the grid that narrows the list by text.

  1. A TextBox above the grid. Results either change while typing (TextChanged, as in Lab 2) or after a Search button; both are accepted.
  2. It searches at least one text column with LIKE. Searching two columns with OR is better and is expected for full marks.
  3. An empty box shows everything. An empty box must not cause an error.
  4. No match shows a message, for example "No books match your search.", not just an empty grid.
  5. The search text is passed as a parameter. See requirement 5.
Two text columns, grouped

When you search two columns and also filter, wrap the two LIKE conditions in brackets, or the OR cancels the filter:

SQL
WHERE (@text = N'' OR Title LIKE @pattern OR Author LIKE @pattern)
  AND (@genre = N'' OR Genre = @genre)

Done whenA word that exists in three rows returns exactly those three, and clearing the box brings everything back.

9

Filter or sort

1 pt

One more way to change what the list shows. Choose either of these.

Option A — filter

A ComboBox with the categories of one column and an All item first. Choosing one shows only those rows; All shows everything. As in Lab 2, the year filter.

Option B — sort

A ComboBox labelled Sort by, with at least three choices (for example Title A–Z, Newest first, Cheapest first). Each choice maps to a fixed ORDER BY written in your code.

Search and filter must work together

Typing orwell and then choosing Fiction must apply both, not replace one with the other. Send both values to one repository method that builds one query, as Search(text, genre) does above.

Done whenSearch and filter are both active at the same time, and the grid shows only rows that match both.

10

Input checks

1 pt

The dialog refuses obviously wrong data before it reaches the database.

  1. Required text fields cannot be empty or only spaces: check with string.IsNullOrWhiteSpace.
  2. Every NumericUpDown has a sensible Minimum and Maximum (no year 0, no negative price).
  3. At least one rule of your own that fits your subject: an end date after the start date, a year not in the future, a phone number with at least 9 digits, an e-mail with @.
  4. A failed check shows a MessageBox that says what is wrong, and the dialog stays open with what the user typed. Use return;, as in Lab 2, step 12.

Done whenClicking Save with an empty required field shows a message, the dialog stays open, and nothing is saved.

11

Code quality and README

1 pt
  1. Real names for everything: books, searchText, selectedBook. Not a, x, list1.
  2. No control left with a default name (textBox1, button1, dataGridView1). See the deductions.
  3. Consistent indentation. Edit → Advanced → Format Document (Ctrl+K Ctrl+D) fixes it for you.
  4. No commented-out blocks of dead code, no empty event methods left over from accidental double-clicks, and no test MessageBoxes.
  5. A README.md next to the .sln file with: the project name, one paragraph on what it does, the list of columns, and the exact steps to run it.

Do not just delete the method: the .Designer.cs file still refers to it and the build fails. Open the ⚡ Events list, right-click the event name → Reset, then delete the method.

The "filter by" column is the one that must repeat

In your script, spread the 15 rows across at least three values of that column. A table where all 15 books are Fiction makes the filter look broken even when the code is right. For topic 13 the filter is a BIT: the ComboBox has All, Express, Regular, and both values must appear in the data.

Hard and easy ones

They are all the same amount of work — one table, six features. Topics 3, 11, 16 and 17 have the simplest data to invent. Topic 13 needs a TIME column, which C# reads as a TimeSpan; topic 14 needs a little more thought in the test data.

☆

Your own topic

You may propose a subject of your own instead of choosing from the list. It is marked against exactly the same eleven requirements, so an approved free topic is neither easier nor harder.

Rules

  • One table. No foreign keys, no second table.
  • At least five columns besides Id, of at least two different types.
  • At least one text column that is worth searching — a name, a title, a person.
  • At least one category column with three or more repeating values, to filter by.
  • You can invent 15 realistic rows for it. If you cannot, the subject is too narrow.
  • It is not the Student Registry from Lab 2, and not a near-copy of a topic already taken.

How to propose it

  1. Write the proposal below in one message.
  2. Email it to lasha.iashvili@kiu.edu.ge with the subject C# midterm topic — Surname Firstname.
  3. Wait for the reply. An unapproved topic is not accepted, however good the project is.
  4. The deadline for approval is Sunday 1 November, 23:59. Send it early; you may be asked to change something.

Approved without question

  • Anything with one clear thing you can count: tools, tickets, plants, courses, invoices, matches
  • Something from your own life — your team, your collection, your workplace
  • A subject in Georgian, as long as the table and column names are in English

Refused

  • A chat, a forum, anything with users and passwords
  • A shop with a basket or orders — that is two tables
  • Anything with a login screen
  • Anything that stores photos
The usual mistake with a free topic

Students pick something they are excited about and it quietly needs two tables — orders and products, teams and players, invoices and items. If your one-line description contains the word "and" joining two kinds of thing, it is two tables. Keep the one you care about and drop the other.
